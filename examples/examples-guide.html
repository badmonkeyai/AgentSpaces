Running the examples

Every example runs from the repository root with one Maven command, and every example deploys nothing beyond its own JVMs: no broker, no registry, no scheduler. The peers in a multi-peer example listen on localhost TCP ports and form a real replicated fleet inside the demo.

mvn -q -pl examples/example-01-hello-space exec:java     # any example, by module path

Each example also ships its flow as a JUnit test in the same module, so the demonstrated behavior runs under mvn test and in CI. The single-process examples drive their tests with a TestClock and contain no sleeps; the fleet examples run their tests over real TCP peers.

The table below is the whole catalog. The sequence is deliberate: each example assumes the ideas of the one before it and adds one layer.

aspace://examples/quickstart · example 11

Quickstart

The gentlest start. Two plain classes become a two-peer fleet: a worker that takes orders and ships them, and an auditor that reacts to every shipment with a receipt. The example names no space anywhere, because the binder infers the group's sole registered space; durations read like Spring properties ("10m"); and a @SpaceRef field hands the worker a space handle for a mid-work progress entry.

example-11 — Quickstart.java_□×
@AgentSpec(name = "fulfiller", description = "Ships orders from the shared space",
        goals = {"fulfill orders"})
public static class Fulfiller {

    @SpaceRef                              // injected at bind time; sole space, no name
    private Space space;

    @SpaceTake(lease = "10m", pollTimeout = "300ms")
    public Shipment ship(Order order) {
        space.write(new Progress(order.orderId(), "picking " + order.item()),
                Lease.of(Duration.ofMinutes(5)));
        return new Shipment(order.orderId(), order.item(), "fulfiller");
    }
}
@AgentSpec(name = "auditor", description = "Writes a receipt for every shipment",
        goals = {"account for shipments"})
public static class Auditor {

    @SpaceNotify                           // react to X, produce Y
    public Receipt account(Shipment shipment) {
        return new Receipt(shipment.orderId(),
                shipment.item() + " shipped by " + shipment.by());
    }
}
// entries are plain records; the space replicates them, signed and leased
public record Order(String orderId, String item) {}
public record Progress(String orderId, String note) {}
public record Shipment(String orderId, String item, String by) {}
public record Receipt(String orderId, String summary) {}
✓ two peers on localhost TCP · orders in, receipts out · choreography in one returning method

The main method assembles two TCP peers, binds one POJO on each, writes two orders, and waits for two receipts. The worker's progress markers and the auditor's receipts print at the end, all read back from the space itself.

mvn -q -pl examples/example-11-quickstart exec:java

What to watch for. The whole fleet is one file, and the choreography is one returning method: the auditor never subscribes, never dedupes, and never touches a listener API, because @SpaceNotify carries those disciplines. QuickstartTest runs the same flow as a JUnit test.

aspace://examples/hello-space · example 01

Hello Space

One process, one LocalSpace, and the whole coordination model in miniature. A coordinator writes leased ResearchTask entries; a worker takes the most urgent one and crashes; the take lease lapses and the task reappears; a healthy worker takes it again and completes it, writing a Finding result atomically with the completion. A notification subscription prints every lifecycle event as it happens, so the terminal shows the space thinking.

This is the example to read when you want the four verbs of the space API (write, read, take, notify) with no networking, no peers, and no annotations in the frame. Everything the fleet examples do over TCP, this example does against a single in-memory replica through the same interface.

example-01 — HelloSpace.java_□×
// watch everything that happens to research tasks
space.notify(Template.of(ResearchTask.class),
        (SpaceEvent<ResearchTask> event) ->
                System.out.println("event : " + event.kind() + " " + event.entry().topic()),
        Lease.of(Duration.ofMinutes(5)));

// a coordinator publishes work under a 30-minute lease
space.write(new ResearchTask("agentic memory", 3), Lease.of(Duration.ofMinutes(30)));
space.write(new ResearchTask("tuple spaces", 7), Lease.of(Duration.ofMinutes(30)));
// a worker takes the most urgent task... and crashes (never completes)
TakenEntry<ResearchTask> doomed = space.take(
        Template.of(ResearchTask.class).where("priority", gte(5)),
        Lease.of(Duration.ofMillis(300)), Duration.ofSeconds(1)).orElseThrow();

// the take lease lapses; the task reappears for a healthy worker
Thread.sleep(600);
TakenEntry<ResearchTask> retry = space.take(
        Template.of(ResearchTask.class).where("priority", gte(5)),
        Lease.of(Duration.ofMinutes(10)), Duration.ofSeconds(5)).orElseThrow();
// worker B completes the take and atomically writes its result
space.complete(retry,
        new Finding(retry.entry().topic(), "write/take/complete with leases: it works"),
        Lease.of(Duration.ofHours(1)));

Finding finding = space.read(Template.of(Finding.class), Duration.ofSeconds(1)).orElseThrow();
✓ one process · LocalSpace · every verb of the space API
mvn -q -pl examples/example-01-hello-space exec:java

What to watch for. The crash costs the worker nothing beyond its lapsed lease: no cleanup handler runs, no janitor process exists, and the task's reappearance is the lease system doing its ordinary work. HelloSpaceFlowTest drives the identical flow with a TestClock and no sleeps, which is the pattern to copy for testing your own agents against LocalSpace.

Where the annotations fitThis example calls the core API directly. Example 11 shows the same worker shape as one @SpaceTake annotation on an ordinary method, and example 02 runs many such workers as separate processes draining one shared space.
aspace://examples/research-fleet · example 02

Research Fleet

The replicated-worker demo over the full stack, Layers 0 through 3 on real TCP. A coordinator peer publishes ResearchTask entries into a replicated space; worker peers drain them under the LEASE_RACE strategy; one worker dies mid-task; its take lease lapses; the task reappears; and the fleet finishes everything anyway. Every write, claim, and completion travels as a signed, verified, gossip-replicated delta.

The default invocation runs three peers in one process on localhost ports. The same binary also runs each peer as its own process, which turns the demo into the M1 LAN exercise: start a coordinator, then point workers at it.

example-02 — ResearchFleet.java_□×
// startPeer: identity, transport, membership, and the replicated space
PeerIdentity identity = PeerIdentity.generate();
PeerNode node = PeerNode.builder(identity).build();
node.listen(new TcpTransport(), HOST + ":" + port);
GroupRuntime runtime = node.joinGroup(fleetGroup(),
        new GroupMembership.Config(Duration.ofSeconds(30), Duration.ofSeconds(2), 2),
        seeds);
ReplicatedSpace space = ReplicatedSpace.builder(runtime, "tasks", identity, name)
        .settleWindow(Duration.ofMillis(150))
        .build();
node.startTicking(Duration.ofMillis(250));
Optional<TakenEntry<ResearchTask>> taken = peer.space().take(
        Template.of(ResearchTask.class),
        Lease.of(Duration.ofSeconds(2)), Duration.ofSeconds(2));

if (dieAfter >= 0 && completed >= dieAfter) {
    System.out.println("  [" + name + "] took '" + task.topic()
            + "' and DIED (no complete; the lease will lapse)");
    peer.close();
    return completed;
}
peer.space().complete(taken.get(),
        new Finding(task.topic(), "researched: " + task.topic(), name),
        Lease.of(Duration.ofHours(1)));
// the crashed worker's task reappears after its lease lapses; B sweeps it up
while (coordinator.space().readAll(Template.of(Finding.class), 10).size() < 6) {
    Optional<TakenEntry<ResearchTask>> retry = workerB.space().take(
            Template.of(ResearchTask.class),
            Lease.of(Duration.ofSeconds(2)), Duration.ofSeconds(3));
    if (retry.isPresent()) {
        workerB.space().complete(retry.get(),
                new Finding(retry.get().entry().topic(),
                        "recovered: " + retry.get().entry().topic(), "worker-b"),
                Lease.of(Duration.ofHours(1)));
    }
}
✓ 3 peers on TCP · LEASE_RACE · one crash, six findings, each completed exactly once
mvn -q -pl examples/example-02-research-fleet exec:java   # all three peers, one process

# or one process per peer:
mvn -q -pl examples/example-02-research-fleet exec:java -Dexec.args="coordinator 7451"
mvn -q -pl examples/example-02-research-fleet exec:java -Dexec.args="worker 7452 7451"
mvn -q -pl examples/example-02-research-fleet exec:java -Dexec.args="worker 7453 7451"

What to watch for. Kill a worker process mid-task and watch the task come back for another worker; the coordinator changes nothing about how it writes work. ResearchFleetFlowTest runs the kill-tolerance flow as a JUnit integration test over TCP, and that test is the executable form of the plan's M1 success criterion.

aspace://examples/discovery-cards · example 03

Discovery Cards

Automatic AgentCards become the routing table. A summarizer and a translator live on different peers and publish their cards when they bind; a dispatcher peer asks the ad-cache which agent produces which entry type, then simply writes tasks and reads results. No peer carries configuration naming any other peer.

The cards come from the method signatures the agents already have: binding collects each agent's consumed and produced types and publishes them, TTL-leased and auto-refreshed. Routing by card query means the dispatcher keeps working as agents join, move between peers, or age out of the cache.

example-03 — CardsFleet.java_□×
@AgentSpec(name = "summarizer", description = "Summarizes documents", goals = {"summarize"})
public static class Summarizer {
    @SpaceTake(space = "work", pollTimeout = "PT0.3S")
    public Summary summarize(SummaryTask task) {
        return new Summary(task.document(), "summary of " + task.document());
    }
}

@AgentSpec(name = "translator", description = "Translates text", goals = {"translate"})
public static class Translator {
    @SpaceTake(space = "work", pollTimeout = "PT0.3S")
    public Translation translate(TranslateTask task) {
        return new Translation(task.text(), task.language(),
                "[" + task.language() + "] " + task.text());
    }
}
// who produces Summary? ask the ad-cache, then just write and read
String summarySchema = Summary.class.getName() + "#v1";
List<AgentCard> summarizers = dispatcher.discovery().find(AgentCard.class,
        card -> card.produces().contains(summarySchema));

dispatcher.work().write(new SummaryTask("quarterly-report.pdf"),
        Lease.of(Duration.ofMinutes(10)));
dispatcher.work().write(new TranslateTask("hello fleet", "fr"),
        Lease.of(Duration.ofMinutes(10)));

Summary summary = dispatcher.work()
        .read(Template.of(Summary.class), Duration.ofSeconds(20)).orElseThrow();
✓ cards published on bind · the ad-cache is the routing table · no static wiring
mvn -q -pl examples/example-03-discovery-cards exec:java

What to watch for. The dispatcher's only inputs are the entry types it wants produced. CardsFleetFlowTest runs the flow as a JUnit test. Chapter 5 of the developer guide documents the discovery API the dispatcher uses.

aspace://examples/auction · example 04

Auction

The AUCTION strategy end to end. Two model workers price the same tasks differently through @BidFunction cost models: the mini model bids low on routine work and high on hard work, the premium model's flat rate pays off on the hard work, and the space allocates each task to the lowest bidder. Cost-aware routing lives in the coordination layer itself, and the example runs no dispatcher of any kind.

A bid function is a plain method over the entry, so the cost model is ordinary code: denominate in dollars, tokens, or queue depth, and let FinOps tune it. The demo prints which worker won each task and why the prices differ.

example-04 — AuctionFleet.java_□×
// the small, cheap model: great value on routine tasks, poor on hard ones
@BidFunction(space = "model-tasks")
public double bid(ModelTask task) {
    return 1.0 + task.difficulty() * 2.0;   // 3 .. 21
}

// the premium model: flat pricing that only pays off on hard tasks
@BidFunction(space = "model-tasks")
public double bid(ModelTask task) {
    return 12.0;
}
// the worker only executes tasks its bid won; the space decides
@SpaceTake(space = "model-tasks", pollTimeout = "PT0.3S")
public ModelResult run(ModelTask task) {
    return new ModelResult(task.prompt(), task.difficulty(), "mini-model", bid(task));
}
ReplicatedSpace tasks = ReplicatedSpace.builder(runtime, "model-tasks", identity, agentName)
        .settleWindow(Duration.ofMillis(200))
        .strategy(ConflictStrategyType.AUCTION)
        .build();
✓ 8 tasks, difficulty 1..8 · mini bids 1+2d, premium bids flat 12 · lowest bid takes each
mvn -q -pl examples/example-04-auction exec:java

What to watch for. Routine tasks flow to the cheap capacity and hard tasks flow to the premium capacity with no routing rule written anywhere; the allocation emerges from the two bid functions. AuctionFleetFlowTest asserts the allocation. The strategy table in developer guide chapter 4 places AUCTION next to LEASE_RACE and ORDERED.

aspace://examples/quorum · example 05

Quorum

Capability choreography: two capability services compose into a fleet decision. Push-sum aggregation senses the fleet's average backlog with no collector process; the supervisor opens a scale-up proposal when the average crosses its threshold; every member casts a signed ballot into the vote space; and the quorum decision closes identically on every replica.

The tally stays recomputable by any member from the space itself, which makes this the auditable form of a fleet decision: the proposal, every ballot, and the closure all exist as signed entries, and a reviewer can replay them.

example-05 — QuorumFleet.java_□×
// each member contributes its local backlog; push-sum converges on the average
double[] backlogs = {4, 30, 41, 31};                 // average = 26.5 > threshold 20
for (int i = 0; i < fleet.size(); i++) {
    fleet.get(i).aggregate().start("backlog", backlogs[i]);
}

double sensed = supervisor.aggregate().estimate("backlog").orElseThrow();
supervisor.vote().propose("scale-up-1",
        "Average backlog 26.5 exceeds threshold; add two workers?",
        List.of("approve", "reject"), 4, Lease.of(Duration.ofMinutes(10)));

// members approve when their own backlog says they need help
String ballot = backlogs[i] > BACKLOG_THRESHOLD / 2 ? "approve" : "reject";
fleet.get(i).vote().castBallot("scale-up-1", ballot,
        Lease.of(Duration.ofMinutes(10)));
Optional<VoteCapability.Decision> decision = supervisor.vote().decision("scale-up-1");

System.out.println("decision: " + decision.orElseThrow().winner()
        + " " + decision.orElseThrow().tally()
        + "  (signed ballots, recomputable by any member)");
✓ push-sum sensing, no collector · signed ballots · quorum of 4 closes on every replica
mvn -q -pl examples/example-05-quorum exec:java

What to watch for. The sensing runs with no collector and the vote closes with no counter: aggregation converges by pairwise gossip, and the decision derives from the ballots wherever it is computed. QuorumFleetFlowTest runs the flow as a JUnit test. The vote and aggregate services carry the capability ids aspace:cap/vote and aspace:cap/aggregate, documented in developer guide chapter 5.

aspace://examples/wan-rendezvous · example 06

WAN Rendezvous

Two sites, one fleet. The rendezvous peer at headquarters is the only address anyone received in configuration; peers from both sites join through it, membership and discovery converge across the sites, and remote queries prefer rendezvous peers per SPEC §5.4 and §6.3. The shared task space spans everyone, so work written at one site completes at the other.

Rendezvous is a volunteered topology role, and correctness never depends on it: the role gives newcomers a larger discovery cache to ask first, and the fleet's guarantees come from the signed, replicated state underneath.

example-06 — WanFleet.java_□×
// hq volunteers the RENDEZVOUS role; every other peer knows only port 7491
Peer hq = startPeer("hq-rendezvous", 7491, 0, true);
Peer siteA1 = startPeer("siteA-analyst", 7492, 7491, false);
Peer siteA2 = startPeer("siteA-worker", 7493, 7491, false);
Peer siteB1 = startPeer("siteB-analyst", 7494, 7491, false);
Peer siteB2 = startPeer("siteB-worker", 7495, 7491, false);

// the role is one builder call on the node
PeerNode node = PeerNode.builder(identity)
        .roles(rendezvous ? Set.of(PeerAdvertisement.PeerRole.RENDEZVOUS) : Set.of())
        .build();
// site B writes; site A takes and completes; site B reads the result
siteB1.tasks().write(new SiteTask("reconcile ledgers", "site-B"),
        Lease.of(Duration.ofMinutes(10)));

var taken = siteA2.tasks().take(Template.of(SiteTask.class),
        Lease.of(Duration.ofMinutes(5)), Duration.ofSeconds(15)).orElseThrow();
siteA2.tasks().complete(taken, new SiteResult(taken.entry().description(),
        taken.entry().origin(), "site-A"), Lease.of(Duration.ofHours(1)));

SiteResult result = siteB1.tasks()
        .read(Template.of(SiteResult.class), Duration.ofSeconds(15)).orElseThrow();
✓ 5 peers, 2 sites · one configured address · the space spans everyone
mvn -q -pl examples/example-06-wan-rendezvous exec:java

What to watch for. Count the configured addresses: one. Everything else about the two-site topology assembles itself through the rendezvous peer. WanFleetFlowTest runs the flow as a JUnit test. Relay for NAT-restricted peers and group payload encryption over the WAN follow in later milestones (plan M3).

aspace://examples/a2a-fleet · example 07

A2A Fleet

An A2A client drives a P2P fleet through one gateway. Worker agents join a replicated task space over TCP and publish AgentCards; the gateway serves those cards on the standard A2A discovery surface (/.well-known/agent-card.json) and speaks the A2A task surface as JSON-RPC over HTTP. message/send writes a leased task entry into the space; tasks/get reads the task's state out of space semantics, reporting submitted while unclaimed, working while an agent holds the take lease, and completed once a result entry exists; tasks/cancel withdraws the entry.

The demo sends "reconcile the ledgers" to the analyst agent with a plain HTTP client and polls the task to completion. The A2A client never sees the space, the fleet never sees HTTP, and the gateway is the entire boundary between the two. Crash tolerance carries straight through the standards-based interface: a worker that dies mid-task lets its take lease lapse, and the task honestly reports submitted again for another worker.

example-07 — A2aFleet.java_□×
// one gateway serves every discovered card and binds the A2A task surface
try (A2aGateway gateway = new A2aGateway("a2a-fleet", "AgentSpaces demo",
        () -> gatewayPeer.discovery().find(AgentCard.class, c -> true))
        .taskBinding(new A2aTaskBinding(gatewayPeer.tasks()))) {

    int port = gateway.start(0);
    // cards now serve at /.well-known/agent-card.json;
    // JSON-RPC serves at /agents/{name}
}
// a plain HTTP client speaks standard A2A JSON-RPC; no AgentSpaces types
POST /agents/analyst
{"jsonrpc":"2.0","id":1,"method":"message/send","params":
 {"message":{"role":"user","parts":[{"kind":"text",
  "text":"reconcile the ledgers"}],"messageId":"m1"}}}

// then poll until the space's take lease semantics report completion
{"jsonrpc":"2.0","id":2,"method":"tasks/get","params":{"id":"..."}}
// submitted -> working -> completed (or submitted again after a crash)
// the analyst never sees HTTP: it takes and completes entries like any worker
var taken = worker.tasks().take(
        Template.of(A2aTaskEntry.class).where("agent", eq(worker.name())),
        Lease.of(Duration.ofMinutes(1)), Duration.ofSeconds(2));
taken.ifPresent(t -> worker.tasks().complete(t,
        new A2aTaskResult(t.entry().taskId(), worker.name(),
                worker.name() + " says: worked '" + t.entry().text() + "'"),
        Lease.of(Duration.ofHours(1))));
✓ JSON-RPC over HTTP · /.well-known/agent-card.json · the gateway is the entire boundary
mvn -q -pl examples/example-07-a2a-fleet exec:java

What to watch for. One gateway peer opens the door for the whole fleet, so individual agents never expose an inbound endpoint. A2aFleetFlowTest runs the flow as a JUnit test. Developer guide chapter 8 covers the gateway alongside the wire-compatible Python and TypeScript clients.

aspace://examples/intake-fleet · example 08

Intake Fleet

The document intake fleet from USE-CASES.md, and the first of the applied examples. Hard-to-read scans enter the space; two extraction agents each produce a candidate reading with a confidence score; the fleet closes a signed quorum vote on which reading to trust; and an auditor files the winning candidate. The filing carries the whole provenance chain as signed entries: the scan, both candidates, every ballot, and the filing itself, all replayable by a compliance reviewer.

The pipeline is service choreography end to end. Each stage consumes the entries the previous stage produced, the vote capability supplies the quality gate, and no orchestrator process exists anywhere in the example. Adding a third extraction agent means binding a third agent; the vote absorbs it.

example-08 — IntakeFleet.java_□×
// each extractor reacts to every scan with a candidate reading + confidence
peer.intake().notify(Template.of(ScanEntry.class), event -> {
    ScanEntry scan = event.entry();
    // a sloppy extractor misreads digits; a careful one does not
    peer.intake().write(new ExtractionCandidate(scan.scanId(), peer.name(),
                    taxpayerId, amount, skill),
            Lease.of(Duration.ofMinutes(10)));
    castBallotWhenBothCandidatesVisible(peer, scan.scanId());
}, Lease.of(Duration.ofHours(1)));
// the auditor opens the vote; every agent backs the highest-confidence reading
auditor.vote().propose("scan-" + scanId,
        "Which reading of scan " + scanId + " do we trust?",
        candidates.stream().map(ExtractionCandidate::extractor).sorted().toList(),
        quorum, Lease.of(Duration.ofMinutes(10)));

String best = candidates.stream()
        .max(Comparator.comparingDouble(ExtractionCandidate::confidence))
        .orElseThrow().extractor();
peer.vote().castBallot("scan-" + scanId, best, Lease.of(Duration.ofMinutes(10)));
// the winning candidate files, stamped with the quorum tally that approved it
FilingEntry filing = new FilingEntry(scanId, chosen.extractor(),
        chosen.taxpayerId(), chosen.amount(),
        String.format("%d-vote quorum %s", quorum, decision.get().tally()));

auditor.intake().write(filing, Lease.of(Duration.ofDays(1)),
        Map.of("stage", "filed"));
✓ scan → candidates → ballots → filing · every stage a signed entry · no orchestrator
mvn -q -pl examples/example-08-intake-fleet exec:java

What to watch for. The provenance chain assembles itself from entries the stages already write, because every entry is signed by its producer; the audit trail costs the pipeline no extra code. IntakeFleetFlowTest runs the flow as a JUnit test.

aspace://examples/fleet-console · example 09

Fleet Console

The fleet console from USE-CASES.md as a served surface. Everything shown derives from state the fabric already maintains: membership answers "who is alive", discovery answers "who can do what", and the replicated space answers "what is the fleet working on". The console runs no telemetry pipeline and no metrics database; it joins as one more read-only peer, and agentspaces-console serves its view three ways: a single-file web UI, a HAL+JSON API walkable from /api/v1, and a Server-Sent Events activity stream.

The demo starts a small working fleet, prints the console URL, and keeps the fleet busy while you watch. Agents carry zero instrumentation, which is the point: observability comes from the coordination state, so every fleet built on the fabric gets the console with two configuration properties.

example-09 — FleetConsole.java_□×
// everything the console shows derives from state the fabric already holds
ConsoleView view = ConsoleView.builder()
        .space("tasks", peer.tasks(), TaskEntry.class)
        .results("tasks", FindingEntry.class,
                entry -> ((FindingEntry) entry).worker())
        .members(() -> peer.runtime().membership().allMembers())
        .discovery(peer.discovery())
        .build();

FleetConsoleServer server = FleetConsoleServer.builder(view)
        .fleetName("console-fleet")
        .panel(storyPanel(view))                       // ConsolePanel extension point
        .commandAndControl(commander, token)
        .build();
// workers honor operator directives through a DirectiveGate in the work loop
try (DirectiveGate gate = DirectiveGate.attach(peer.control(), peer.name())) {
    while (!Thread.currentThread().isInterrupted()) {
        if (gate.draining()) {
            return;              // commanded to drain: finish and stop for good
        }
        if (gate.paused()) {
            sleepQuietly(200);   // commanded to pause: hold off taking
            continue;
        }
        // ... take, work, complete ...
    }
}
// the demo's scripted C2 pass, all through the control space, all audited
commander.broadcast("PAUSE", "worker-b", "operator");
commander.execute("dispatch-task",
        Map.of("topic", "operator-dispatched", "priority", "9"), "operator");
// the task queues while worker-b holds...
commander.broadcast("RESUME", "worker-b", "operator");
// ...and worker-b takes it on resume
✓ web UI · HAL+JSON at /api/v1 · SSE activity stream · zero instrumentation in any agent
mvn -q -pl examples/example-09-fleet-console exec:java    # then open the printed URL

What to watch for. Pause a worker from the console mid-run and watch its queue hold; every command executes under the console peer's signed identity, attributed to the named operator, and lands in a durable audit space. FleetConsoleFlowTest runs the flow as a JUnit test, and the fleet room gives the operator's tour of the same surface.

aspace://examples/data-fleet · example 10

Data Fleet

The enterprise economics in one demo (ENTERPRISE §3). A connector peer holds an orders table and advertises it as a leased AssetCard; analyst agents discover it by meaning through the semantic-discovery capability, then query it through the space. The first identical query per freshness window executes against the source; every later one reads the leased result at replica speed.

The counters print the money: executions against the source on one line, answers the space already held on the other. Freshness is a lease, so staleness has a bound you choose per asset, and the cached result ages out on its own with no invalidation logic anywhere.

example-10 — DataFleet.java_□×
// the connector wraps a table and advertises it as a leased AssetCard
TableAssetProvider provider = new TableAssetProvider("orders",
        "postgres://ops/public.orders",
        "Customer order history with line items and settlement status",
        "com.example.OrderRow#v1", Duration.ofMinutes(5), rows);

ConnectorRuntime connector = new ConnectorRuntime(connectorPeer.data(),
        connectorPeer.discovery(), connectorPeer.node().identity(),
        "pg-connector", provider, connectorPeer.runtime().id(),
        InstantSource.system(), Duration.ofMinutes(1));
connector.start();
// the analyst never learns an address; it asks for the data by meaning
var matches = analystA.semantic()
        .remoteQuery("who holds customer order history?", 3,
                Duration.ofSeconds(2));
AssetCard card = (AssetCard) matches.get(0).advertisement();
// card.asset()="orders", card.uri(), card.freshness() -- all from the ad
DataQueryClient clientA = new DataQueryClient(analystA.data(), "analyst-a");
DataQueryClient clientB = new DataQueryClient(analystB.data(), "analyst-b");

var first = clientA.fetch(card.asset(), Map.of("region", "eu"),
        Duration.ofSeconds(10)).orElseThrow();   // fromCache=false: hits the source
var second = clientB.fetch(card.asset(), Map.of("region", "eu"),
        Duration.ofSeconds(10)).orElseThrow();   // fromCache=true: the space held it
var third = clientB.fetch(card.asset(), Map.of("region", "us"),
        Duration.ofSeconds(10)).orElseThrow();   // new query: hits the source

System.out.println("source executions: " + provider.executions());  // 2 of 3
